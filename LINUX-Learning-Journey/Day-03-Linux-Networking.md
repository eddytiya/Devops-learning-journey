🚀 Linux for DevOps — Day 3: Networking Commands

Today I practised Linux networking and troubleshooting commands on an AWS EC2 Ubuntu server.

What I worked on:

✅ Connectivity and packet-loss testing with ping
✅ Active connections and listening ports with netstat and ss
✅ Network-interface inspection using ifconfig and ip addr
✅ Network-path analysis with traceroute, tracepath, and mtr
✅ DNS troubleshooting with nslookup and dig
✅ TCP port testing with telnet
✅ HTTP requests and downloads using curl and wget
✅ Routing-table inspection with route and ip route
✅ Firewall-rule inspection using iptables
✅ Continuous command monitoring with watch
✅ Authorized port scanning using nmap

I also learned from several command errors:

• Command spelling and option placement matter
• DNS tools require hostnames—not complete URLs
• Network-interface names vary between systems
• HTTP methods should be written correctly
• HTTP 404 means the requested resource does not exist
• Modern commands such as ss and ip are preferred alternatives to netstat and ifconfig

A valuable part of today’s session was learning how to interpret the output—not merely memorizing commands.

I now have a better understanding of packet loss, latency, listening ports, DNS answers, routes, HTTP status codes, firewall chains, and network scan results.
